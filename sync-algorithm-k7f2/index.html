How the sync planner decides

An interactive walkthrough of tools/sync_plan.py. Change the op list or the settings and every section updates. The engine on this page is a JavaScript copy of the Python that is tested against the same reference cases.

0Your input

The Mastercam op list, in run order for each spindle: <name>_2<H/V> <offset><rotation><tool> := <min>:<sec>

Settings (same names as in sync_plan.py)

Lockout = seconds V cannot cut while H moves the B. V's tool change happens before its (WAIT), while H is still cutting or positioning.

1The question

Two things are already fixed: H's order and V's order. H's list gets cut into stretches wherever H changes tool or rotation (a B event), because the B moves there and nothing may cut. V's list has to be cut into the same number of groups: one group of V work per H stretch. A group can be empty.

So the only decision is where to cut V's list. Each cut is a V (WAIT). The best cuts are the ones that make the whole cycle shortest, which is the same as making H wait the least.

3Why not try every split? (and why it's not the traveling salesman)

The traveling-salesman problem is hard because it has to choose an order, and the number of orders explodes. Here both orders are fixed by the list. Only the cut points are left, and those can be solved exactly with a table. This is called dynamic programming.

"Every split" = every way to place the cuts (the test file checks the planner against exactly this for small lists). "Table" = how many cells × candidates the planner actually evaluates.

4The ingredients

H stretches

Walk H in order. A new stretch starts when the tool or the rotation digit changes. Its lockout is the B-move time V has to sit out.

V pieces

V changes tools before its (WAIT), so each V op's tool change is moved onto the op before it. pre = V's very first tool change.

Cost of one stretch

stretch_cost(s, W):                      W = V's pieces in this stretch
  if s is the first stretch and the cycle does NOT start with a B event:
      return max(H[s], pre + W)              V just runs alongside H
  lead = pre if s is the first stretch else 0  (H waits for V's first tool change)
  return lead + max(H[s], lockout[s] + W)    V starts after the B move

If lockout + W is bigger than H, H waits the difference. That's the only place H ever waits.

5Step through the table

best[s][j] = the shortest time to finish H stretches 1…s with V pieces 1…j done. Each cell looks at every i: "V had done i pieces before stretch s, and does pieces i+1…j during it", and keeps the cheapest. Every cell only needs the row above it, so nothing is ever tried twice.

H stretches
V pieces: ■ this stretch's candidate group

Rows: stretches done (s). Columns: V pieces done (j). Small number = from (where that stretch's V group started). ← → space

6The answer

Walk back from the bottom-right cell: from[s][j] says where stretch s's V group started, which is the cell to look at in the row above. Each step back is one V (WAIT).
